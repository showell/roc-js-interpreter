# x86: the JavaScript subset compiled to x86-64, in Roc alone

The code here was written by AI coding agents (Claude), with human supervision.

This folder is the start of an ahead-of-time compiler for the JavaScript subset that `js/` interprets. It will take a program through the interpreter's own front end (`js/roc/`'s Lexer, Parser, Resolve and Compile, to `Bytecode`) and turn the bytecode into a static Linux x86-64 executable. Roc writes every byte of that executable: there is no assembler, linker, LLVM or libc in the product, and the binary needs none to run.

## The milestones

1. **Hello, world.** The instruction encoder, the ELF writer, and the `write` and exit system calls. *Done* (below).
2. **Numbers and functions.** Doubles, calls and returns, `if` and loops; `fib` compiled and timed against node and the VM. *Done* (below).
3. **Heap values with a bump allocator, no collector.** Objects, arrays, strings; as many corpus programs as fit in memory without collecting. *Done* (below): 9 of the corpus's 61 programs, then closures and functions as values, and the array methods that take a function: 14 of 61; then the cheap operators and exceptions: 17 of 61; then console.log's columns, `Math`, `String`, `Object`'s listings, more methods and the spreads: 31 of 61.
4. **The runtime in the subset.** `console.log`'s formatting, Map and Set, number to string, written in the JavaScript subset and compiled by this compiler.
5. **The collector,** with the shadow stack as its roots, and the whole corpus held to node.
6. **Type specialization,** for long numeric loops.

## What works now (2026-11-25: columns, builtins, methods and spreads)

- `roc/X86.roc` encodes the instructions the milestones so far need: `mov` (register, immediate, memory, and `movabs` for an immediate past 32 bits), `lea`, `add`, `sub`, `and`, `or`, `xor`, `cmp` (register or immediate), `imul`, `div`, `idiv`, `cqo`, `neg`, `test`, `shl`, `shr`, `sar`, `setcc`, `movzx` of a byte register or of a byte of memory, a byte store, `rep movsb`, `push`, `pop`, `jmp`, `jcc`, `call` (each with a rel32), `call` of a register, `ret`, `syscall`, and the SSE2 doubles `movsd`, `addsd`, `subsd`, `mulsd`, `divsd`, `sqrtsd`, `ucomisd`, `cvtsi2sd`, `cvttsd2si` and `movq`. A memory operand is a base register, an optional scaled index and a displacement, or a displacement from `rip`. Every general register is 64 bits wide; a byte operand is one of `al`, `cl`, `dl` and `bl`, which need no REX prefix. Each instruction's bytes are held to its encoding by an `expect`, 98 of them, including the corner cases of the encoding: `rsp` and `r12` as a base (a SIB byte), `rbp` and `r13` with no displacement (a zero byte of it), and displacements and immediates at the edges of 8 and 32 bits.
- `roc/Assembly.roc` assembles a list of instructions, labels and data into code: a jump, a call or a `lea` that names a label gets a placeholder rel32, patched once every label's place is known, and a `Distance` is 8 bytes holding a label's address less its own, so a record in the read-only segment can name code with no address fixed.
- `roc/Elf.roc` wraps the code as a static executable: an ELF header, one program header and one loadable segment, read and execute, mapped at 0x400000, entry at the code's first byte. The data (the string to print) is read-only, so it shares that segment.
- `roc/Hello.roc` is the driver: given a text, it writes the executable that prints it and exits 0. The hello-world binary is 176 bytes.

- `roc/JsToX86.roc` is the compiler: `js-x86 "<program>"` parses and compiles the program with js/roc's own front end, by import (`js/roc/main.roc` makes `Ast`, `Bytecode`, `Compile` and `Parser` a package), lowers the bytecode (`roc/Lowering.roc`), and writes the executable. `roc/Runtime.roc` is the machine code every executable carries beside its own (about 15 KB of it): the start, the allocator, buffered output, the stops, and the routines below. `roc/Boxing.roc` holds a value's layout, and `roc/Emit.roc` short builders for the statements the runtime is written in, one instruction a line.

Roc's default platform writes only text to stdout, so each driver prints the executable as hex, and `executables.shale` turns each pair of digits back into its byte. The scripts decide no byte; they only carry them to the file.

**How the encodings were checked:** each `expect`'s bytes were disassembled with binutils' `objdump -D -b binary -mi386:x86-64 -M intel` during development and read back as the instruction the `expect` names, all 98 of them; the hello-world binary was read with `readelf -h -l` and its code with `objdump`. The product and its checks never run either tool.

## What the compiler compiles

**A value is NaN-boxed, and its kind is known ahead of time where it can be.** Every value's 8 bytes are its boxed bits (`roc/Boxing.roc`):

| top 16 bits | value | low 48 bits |
|---|---|---|
| below 0xFFF9 | a number | (the IEEE double's own) |
| 0xFFF9 | `undefined`, `null`, `false`, `true` | 0, 1, 2, 3 |
| 0xFFFA | a string | its address |
| 0xFFFB | an array | its address |
| 0xFFFC | a plain object | its address |
| 0xFFFD | a function | its closure record's address |
| 0xFFFE | a Map, a Set or an iterator | its record's address |

A number is its double, unchanged; the NaNs x86-64 makes (0x7FF8... for `NaN`, 0xFFF8... for `0 / 0`) lie below every tag, so a value is a number exactly when it is below 0xFFF9 shifted into place, one unsigned compare, and no arithmetic can make a tag. Lowering walks each function's instructions keeping the kind of each slot of the frame and each place on the bytecode's stack: a number, a boolean, `undefined`, `null`, a string, an array, an object, or `Value`, a value whose kind isn't known before it runs; or what takes no bytes (a function by the code it runs, `console`, `console.log`, an array's method looked up). Where two ways meet with two value kinds (a jump's target, a loop's head) the place becomes a `Value`; a loop whose body changes a kind widens its head and lowers the function again. Since a value's bits are the same whatever is known of it, widening costs no code. A known kind lets the code skip the tag's test: two numbers add with `addsd` and nothing else, as in milestone 2, so fib's code is unchanged but for the stack's check. A `Value` goes through the runtime, which tests the tag (`runtime_add`, `runtime_strict_equal`, `runtime_compare`, `runtime_truthy`, `runtime_check_number` before arithmetic). A function's parameters and its result take their kinds from the whole program: each pass meets every call's argument kinds and every return's kind per function, until both settle.

**Functions and closures.** A function's closure record is 8 bytes holding the distance from them to the code a call through the value enters, 8 holding the distance from them to the text console.log writes (`[Function: f]`, `[Function (anonymous)]`), 8 holding the count of captures, then each capture's cell's address, 8 bytes each. Distances, not addresses, so the same layout serves a record on the heap and one in the read-only segment. A function whose captures are all functions known before the program runs (`statics_of` in `Lowering.roc`; fib, which captures only itself, is one) takes no bytes where its kind is known: it is called directly, as in milestone 2, and only where it is used as a value (stored, passed, returned, put in an array or an object, printed) does it become its record in the read-only segment, with no captures. Any other function's `MakeClosure` takes its record from the heap as it runs. A variable a closure captures that holds a value lives in a cell of 8 bytes on the heap, made when its scope starts (the VM's `NewBox`, `FreshBox` and `FilledBox`, and `CopyBox` for a C-form `for`'s next pass), its slot holding the cell's address and its kind `Value`, since writes through other closures are not seen by a walk of one function. A call of a function whose code is known is a direct call, `rbx` holding the record when it has one; the entry copies its captured cells from the record to its slots. Any other call is through the value: stopped unless it is a function, its record in `rbx`, the arguments pushed, their count in `rcx`, and a call of the record's value entry, which takes a missing parameter as `undefined` and leaves an extra argument unread. A function a value may hold takes `Value` parameters (it is `escaping`, worked out with the parameters' kinds until both settle), since no call shows what reaches it that way; one only called directly keeps the kinds its calls give, so fib's code is unchanged. A method call on an object reads the property and calls it through its value. A function whose parameters have a pattern, a default or a rest takes its arguments as a call through a value passes them, counted in `rcx`, by either entry, and packs them into an array in its slot (`runtime_pack`), which its own code takes apart.

**Exceptions.** `[r13 + 16]` holds the innermost `try`'s handler, a record of three values on the machine's stack: the handler before it, the frame's `rbp`, and the code a throw enters. `EnterTry` pushes one and `LeaveTry` pops it (every way out of a `try` but a throw passes a `LeaveTry`, the front end's `tries_left`). A throw (`runtime_throw`, the value in `rax`) sets `rsp` to the record, takes the handler before it back, restores `rbp` and returns into the code the record names, which puts the value where the bytecode's stack had its top at the `EnterTry` (a `finally`'s line and column, 0 and 0, under it) and jumps to the handler's instruction. Every frame and runtime routine between is left as it stands, so a throw from a callback of `map` or from a call thousands deep lands the same way. Since a throw may come from anywhere in the `try`, after its variables changed kinds, each variable holds a `Value` at the handler. `new Error(m)`, `TypeError`, `RangeError`, `ReferenceError` and `SyntaxError` make an object holding `name` and `message` and a key no program can name (one byte, 0xFF; a program's strings are ASCII), which marks it an error, so console.log of one stops rather than print what node wouldn't. The stack's overflow throws node's RangeError where a `try` waits.

**The heap and the runtime's registers.** The start maps 1 GiB (`mmap`, `MAP_NORESERVE`, so only what is touched is memory) and sets four registers that no other code writes: `r12` the lowest the stack may reach, `r13` the runtime's state (the output buffer's fill, node's inspect depth, then 64 KiB of buffer), `r14` the heap's end, `r15` its next free byte. `runtime_allocate` is a bump allocator, 8-byte aligned; nothing is freed, and past the end the program stops with `x86: out of memory: the heap of 1 GiB is full, and no collector runs yet` on stderr and exit 1. A string is its length in 8 bytes, then its bytes; a literal sits in the read-only segment in the same layout, each text once. An array is its length, its capacity and its items' address, 8 bytes each; an object is its count, its capacity and its entries' address, 16 bytes each (a key's address and the value), searched in order. A full list is copied to one twice its size.

**Output is buffered.** console.log writes into the buffer, which is written when the next bytes wouldn't fit, before a stop's message, and at the exit; a write the kernel cuts short is written on until every byte is. `many-lines.js` prints 20,000 lines through it.

**Stack overflow.** Every function's entry checks its frame against `r12`, 6 MiB below the start's stack (Linux gives 8 MiB; the rest is the runtime's). Past it the program writes `RangeError: Maximum call stack size exceeded` to stderr and exits 1, as node does for an uncaught RangeError, whose stderr has that same line after the source line and a caret, and a stack trace after. How deep differs: node throws between 9,000 and 10,000 calls of `function d(n) { return n === 0 ? 0 : 1 + d(n - 1); }`, the executable between 80,000 and 90,000 (its frames are about 72 bytes), so a recursion between the two runs here and throws in node. A `try` that waits catches it as node's RangeError.

**A frame is fixed per function**: below `rbp`, its slots, then the bytecode's stack as deep as the function ever makes it, so every push and pop is a load or a store at a known place. A call pushes its arguments, the last first, and the callee copies them to its parameters' slots; the result comes back in `rax`.

**Compiled:** `**` of a whole base and a whole exponent of at least 0 (by squaring, each step held to 2^53, so every product is exact); `typeof`; `??` and defaults; `switch`; parameters and declarations with patterns, defaults and rests; `try`, `catch` (with a pattern or no binding), `finally`, `throw` of any value, and `new` of the five error classes; numbers (SSE2), booleans, `undefined`, `null`, strings, arrays and plain objects in variables, parameters, results and on the stack; anything else by its bits, so an array or object by identity); unary `- + !`, `++`, `--`, `+=` (a string's too); `if`, `while`, `for`, `for ... of` over an array or a string, `break`, `continue`, `&&` and `||`; functions declared or made by an expression or an arrow anywhere, as values in variables, arrays, objects, arguments and results, with closures over variables that hold values, called by name, through a value or as an object's method, with returns and recursion; `NaN` and `Infinity`; string literals, `+` with a string (`String(v)` of a number, a boolean, `undefined` or `null`), template strings, `.length`, `s[i]`; array literals, `a[i]`, `a[i] = v` (one past the end appends), `.length`, `push` of one or more items, `pop`, `map`, `filter`, `forEach` and `reduce` of a function (called with the item, its place and the array, and `reduce` with the value so far first), `join` with a string or none, `slice` with up to two places (negative ones from the end), and a string's `charAt`; object literals, `o.k`, `o.k = v`, `o[k]` and `o[k] = v` with a string or whole-number key; `Math`'s `floor`, `ceil`, `round`, `trunc`, `abs`, `sign`, `sqrt`, `pow` (as `**`), `max` and `min` (of any count, NaN and the zeros' signs as node has them), `PI` and `E`, and `typeof` of `Math` and its functions; `String(v)`, which makes an array its items' texts joined with `,`, a plain object `[object Object]` and an error its name and message, as templates and `+` with an array or object now do; `Object.keys`, `values` and `entries` of a plain object; the array methods `concat`, `some`, `every`, `find`, `findIndex` (to the length they started with, as node), `indexOf` (by `===`) and `includes` (NaN found), both from a place, `sort` (stable, by the function's answer above 0, or by the items' texts, `undefined` last) and `reverse`; an object pattern's rest; and `console.log` of any number of any of these.

**console.log matches node's `util.inspect` for what is compiled:** a string is written raw at the top level and quoted inside an array or object, `'...'`, or `"..."` when it holds a `'`, with `\n`, `\t`, `\\`, `\r`, `\b` and `\f` escaped; a key is bare when it is an identifier (`[a-zA-Z_][a-zA-Z_0-9]*`) and quoted otherwise; an array or object is `[ 1, 2 ]` or `{ a: 1, b: 'x' }` on one line when node's rule puts it there (fewer than 3 levels nested below it, no item holding a line break, and its items' lengths plus 2n, the indentation and 11 at most 80), and one item a line, indented two spaces a level, otherwise; `[]`, `{}`, and `[Array]` and `[Object]` past depth 2. **An array of more than 6 items is laid out in columns** when node's `groupArrayElements` does it (`runtime_columns` in `Runtime.roc`): when three of the longest fit a line and the items are alike in length (their total over the widest above 5, or the widest at most 6), the columns are the least of `round(sqrt(2.5 * biased * n) / biased)` (`biased` the widest plus 2, less 3, less `sqrt(actual - total / n)`, at least 1), `floor((80 - indentation) / actual)`, 12 (node's `compact`, 3, times 4) and 15; each row's items are padded to their column's widest, on the left when every item is a number and on the right otherwise, and the rows are written one a line.

**Refused, by name, before a byte is written:** classes (`a class is not compiled yet`: the parser's desugaring needs `NewInstance` and `this` cells, which the corpus's class programs pair with `Math`, `try` and printing an instance), a function known by its code met with another kind where two ways meet (`cond ? f : g`); an optional chain (`a?.b`, the VM's `ShortIfNullish`); an assignment to a variable that may not be declared yet where it runs (a `switch`'s, which node throws a ReferenceError for); every builtin but `console.log`, `NaN`, `Infinity`, the error classes, `Math`, `String` and `Object` (so Map, Set, `Number`, `Array`, the timers); `Math.sin`, `cos`, `tan` and `atan` (node's last digits are V8's port of fdlibm's), `Math.pow` with fewer than two arguments, `String.fromCharCode`; every method but those above (so `splice`, `lastIndexOf`, a string's `slice`), and `join` with a separator that isn't a string; a string that isn't ASCII (a length here counts bytes, JavaScript's UTF-16 units); a direct call of a function known before the program runs with more or fewer arguments than it has parameters (a call through a value takes any count); an operator on kinds known to need a coercion (`true + 1`, `"a" * 2`); and every bytecode instruction not named above. `x86/tests/refused/` holds one program for most of them.

**Stopped as it runs, where only the value decides,** with a line `x86: ... is not compiled yet` on stderr and exit 1, so the output can't pass for node's: arithmetic or an ordering on a `Value` that turns out not to be numbers (or two strings); a call of a value that is not a function (node throws a TypeError); a string made of a function (node gives its source); `Object.keys` and its kin of anything but a plain object; an error spread or taken by a rest (its name and message are own properties here); a `sort` whose function answers something but a number, a boolean or `undefined`; `split` at a value that isn't a string; `indexOf` from a place that isn't a number; `reduce` of an empty array with no first value (node throws); `+` of two values neither a string nor both numbers; `%` of numbers that aren't whole; an array written past its end, leaving holes; `**` of numbers that aren't whole, a negative exponent or a power past 2^53; an object pattern of `null` or `undefined` (node throws a TypeError); a throw nothing catches (node exits 1, after its report of the source line); console.log of an error (node writes its stack); an object given an integer key (node lists those first, which a list in insertion order doesn't); an index or property on a value that has none here; console.log of an array or object of more than 100 items (node writes the first 100 and a count); of a string holding both quotes or another control byte inside an array or object; and of a number that isn't an integer of at most 2^53 (fractions are milestone 4's shortest round-trip printing). Numbers are written as node writes them when they are such integers, `NaN`, `Infinity`, `-Infinity` or `-0` (and `String(-0)` is `"0"`).

## fib, compiled and timed (2026-11-24)
`x86/fib.js` is the recursive `fib(n)` printing `fib(22)` and `fib(30)` (17711 and 832040). Each time is the best of three runs, wall clock and CPU, on the 2-core box, node v22; js-vm is the bytecode VM's release build, from the shared build cache. The last run (2026-11-25, the load average at 3.26, 1.78, 1.44, another lane's work beside it):

| program | the executable | node | js-vm (release) |
|---|---|---|---|
| fib(22) | 1 ms (0 ms CPU), 17,647 bytes | 96 ms | 97 ms |
| fib(22) and fib(30) | 21 ms (20 ms CPU), 17,715 bytes | 65 ms | 6,289 ms (4,522 ms CPU) |

The columns, the builtins, the methods and the spreads left fib's code as it was: 21 ms, 20 ms CPU, as on 2026-11-24 (21 ms, 19 ms CPU, at a load of 0.90). `fib` captures only itself, so it is known before the program runs, takes no bytes, is called directly and keeps its `Number` parameter; its times are milestone 3's (20 ms, 19 ms CPU). The executable grew by the runtime's new routines (about 6.3 KB this round: the columns, Math, the listings, the searches, the sort, split and the spreads), which every executable carries whatever it uses. Milestone 2's numbers were 1 ms and 21 ms with 1,010- and 1,089-byte executables. On fib(30), 1.6 million calls, node's optimizing tier makes its own work about 16 ms, the executable's about 20: fib's kinds are all known, so no tag is tested, but the baseline code keeps every value in memory and moves it through `rax` or `xmm0` an instruction at a time, which milestone 6's register allocation and specialization are for. The VM is about 220 times slower than the executable there.

## Running it

From the repository's root:

    shale x86/hello.shale            # the encoder's expects, then the hello-world executable
    shale x86/programs.shale         # each program in x86/tests/ held to node, each in tests/refused/ to its refusal, the corpus to x86/corpus.txt
    shale x86/programs.shale corpus=report   # the same, with each corpus program's reason, grouped
    shale x86/fib.shale              # the compiler's expects, fib held to node, then the times
    shale x86/fib.shale timing=0     # the same without the times

`hello.shale` runs the backend's 113 expects (`roc test x86/roc/Hello.roc`, which runs every imported module's), builds the driver on the dev backend, writes the executable under the build mount, runs it, and holds its output (`Hello, world!` and a newline) and its exit code (0) exactly. `programs.shale` compiles each program in `tests/` and holds what its executable prints and its exit code to node's, exactly; each program in `tests/refused/` names in its first line the refusal js-x86 must print (`// refused: <text>`) or the line its executable must stop with (`// stops: <text>`); then the corpus, as above. `fib.shale` holds the compiler's 127 expects (the encoder's, Boxing's 3, and js/roc's 11 that the front end brings), then fib to node, then times the executable, node and js-vm's release build; it never starts a release build, and says so when the cache holds none of today's inputs (`tools/roc_build.shale cached=1`). `shale check.shale` runs all three (fib with `timing=0`), and runs `roc fmt --check` and `roc check` over this folder as over the rest.

The drivers alone, once built: `x86-hello "Hello, world!"` and `js-x86 "<program>"` print an executable's bytes as hex; a program js-x86 refuses ends with a line `js-x86: <why>` and exit 1.

`x86/lints.shale` and `x86/accepted_terms.txt` give Shale's Roc lints the manuals' short words (`rax`, `lea`, `rex`), which they would otherwise read as abbreviations.
